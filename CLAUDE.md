# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"Global Flash Gallery" is a WordPress plugin for building image galleries. Despite the name, Flash support was removed in 0.16.0: galleries are rendered only by the jQuery-based JavaScript engine `js/altgallery.js`. The repo root *is* the plugin directory as deployed to `wp-content/plugins/`. It requires PHP 8.2+ (`Requires PHP` header) and was tested with WordPress 7.1 on PHP 8.2, 8.3 and 8.5.

There is no build step, package manager, linter config, or test suite. The only local check is a lint:

```sh
for f in $(git ls-files '*.php'); do php -l "$f"; done | grep -v 'No syntax errors'
for f in $(git ls-files 'js/*.js'); do node --check "$f"; done
```

`php -l` misses whole classes of PHP 8 failures, such as incompatible method signatures, which are fatal only when a class is loaded. Real verification means activating the plugin in WordPress with `WP_DEBUG` and `WP_DEBUG_LOG` on, then checking `wp-content/debug.log`. The official `wordpress:php8.x-apache` and `wordpress:cli` Docker images with the repo bind-mounted into `wp-content/plugins/` work for this.

## PHP / WordPress conventions

- `flgalleryBaseClass::__construct(...$args)` forwards to the subclass's `init()`. `init()` is deliberately **not** declared in the base class, because subclasses use different signatures and PHP 8 rejects incompatible overrides. The base class has `#[\AllowDynamicProperties]` (inherited by subclasses), since code and the commercial add-on attach ad-hoc properties.
- Plugin globals (`$flgalleryPlugin`, `$flgalleryErrors`, …) are declared with `global` at file scope, because WP-CLI includes plugin files from inside a function.
- Read request data defensively (`$_POST['x'] ?? ''`, `wp_unslash()`, `sanitize_*`). WordPress slashes superglobals, and PHP 8 warns on missing keys.
- Gallery types coming from requests must pass `$plugin->isGalleryType()`, because the type ends up in file paths and SQL.
- GD images are objects in PHP 8. `imagegif()` takes no quality argument (passing one is a fatal `ArgumentCountError`).
- Admin JS runs on WordPress's jQuery 3.x. Don't use APIs removed in jQuery 1.9 or 3.0 (`.toggle(fn, fn)`, `.size()`, `$.browser`, `.live()`, `.attr('checked')` for state).

## Releasing

Bump **both** the `Version:` header and `FLGALLERY_VERSION` in `flgallery.php`. Bump `FLGALLERY_JS_VERSION` only when `js/altgallery.js` changes (it is used as a cache-busting query string). If a release needs a data migration, add a step to `flgalleryPlugin::upgrade()` gated on `flgallery_versionValue()`. That function encodes `0.14.1` as `140100` and ignores suffixes such as `b`, and the existing steps show the pattern. `upgrade()` runs on every load, not only on activation.

## Architecture

### Bootstrap and shared state
- `flgallery.php` defines path/URL constants, loads `config.php` (names, table names, directory names), and creates the single `$flgalleryPlugin` (`inc/plugin.class.php`). Its `init()` wires up every hook: the `[flgallery]` shortcode, the widget, the `admin-ajax` actions `flgalleryXml` and `flgalleryPopup` (also `nopriv`), and `flgalleryUpload` (logged-in only).
- Admin classes (`admin`, `adminPage`, `media`) are loaded only when `WP_ADMIN` is defined. Admin menu callbacks must be instance callbacks, because PHP 8 can't call non-static methods statically.
- **Service-locator idiom:** methods begin with `include FLGALLERY_GLOBALS;` (`inc/globals.php`). This brings `$plugin`, `$func`, `$tpl`, `$site`, `$wpdb` into local scope, plus `$admin`, `$admpage`, `$media` in admin. Use this instead of passing dependencies around.
- Errors, warnings and debug messages go through `$this->error()/warning()/debug()` (base class) into globals and are printed by `flgalleryAdmin::printErrors()` etc. Add `?debug` to an admin URL to show debug output (`FLGALLERY_DEBUG`). Activation and upgrade events are logged to `wp-content/flgallery/log.txt`.

### Gallery types (the main extension point)
There are 10 types (`3dWall`, `Art`, `Aura`, `Box`, `Cubic`, `Line`, `PhotoFlow`, `Promo`, `StackPhoto`, `Zen`), and each needs a matching renderer in `altgallery.js`. Each type is defined by files spread across the repo, all keyed by the type name:
- `galleries.xml`: registry (title, description, preview image, demo link), loaded into `$plugin->galleryInfo`.
- `settings/<Type>.xml`: settings schema (`<group>`/`<param>` with `default` and `<input type=…>`). A param inside a group is addressed as `group.param` (e.g. `background.transparent`). Input widgets are generated by `flgalleryFunctions::input()`.
- `tpl/settings/<Type>.html`: admin settings form layout, using `{name.title}`, `{name.input}`, `{name.description}`.
- `tpl/xml/<Type>.xml` and `<Type>-item.xml` (plus `Zen-album.xml`): templates for the XML config file that altgallery reads.
- `img/galleries/<Type>.png` (preview) and an entry in `$this->limitations` (the free-version picture limit) in `plugin.class.php`.
- `*.legacy/` directories (`settings.legacy/`, `tpl/settings.legacy/`, `tpl/xml.legacy/`) are alternate versions used when `flgalleryGallery::isLegacy()` is true.

3D Slideshow was Flash-only. The 0.16.0 upgrade step converts such galleries to `Box`, the type altgallery has always drawn them as.

**External commercial add-on:** `$flgalleryProducts` and `flgallery_commercial_getJS()` are defined *outside* this repo by a paid add-on. They switch off the trial notice and limits, select the legacy variants, and override the JS engine URL. Always guard uses of them with `function_exists`/`empty`. `$flgalleryProducts` is keyed by `flgalleryGallery::getSignature()` (`md5("<Type>.swf")`), so keep that formula even though the SWF files are gone.

### Rendering pipeline
Shortcode `[flgallery id=N]` (optional `popup`, `preview`, `text`) or the widget calls `flgalleryGallery::getHtml()`, which returns:
- a `.flgallery-embed` container sized to the gallery,
- a `<noscript>` list of pictures,
- an inline script from `tpl/altgallery.html` that calls `altgallery(options, selector)` on `DOMContentLoaded`. The options are JSON-encoded in PHP.

`getHtml()` also enqueues the `altgallery` script handle, so the 200 KB engine loads only on pages with a gallery. The handle is registered in `registerScripts()` with an inline shim for `.size()` and `.andSelf()`, which the minified engine needs when jQuery Migrate is absent. `js/altgallery.js` is a minified third-party bundle (it includes jQuery UI), so don't hand-edit it.

The callback in `tpl/altgallery.html` shows the gallery at its configured size and only scales it down to the available width. It measures the embed itself, not its parent, because in block themes the parent is full-width. `getHtml()` collapses its output onto one line, so templates it renders must not contain `//` comments. The popup (`inc/galleryPopup.class.php`) is a standalone page that prints its scripts with `wp_print_scripts()`. Don't add `wp_footer()` to it without `wp_head()`, because that triggers core deprecation notices.

**XML cache:** `getXml()` renders the type's XML templates and writes them to `wp-content/flgallery/xml/<blog_id>/<gallery_id>.xml`. The `flgalleryXml` ajax action serves the cached file, or generates it if missing. Any change to a gallery, its settings, or its images must call `$gallery->clearXmlCache()`, or the front end shows stale data. `flgallery_clearXmlCache()` in `inc/functions.php` clears every cached file recursively.

### Template engine (`inc/templates.class.php`)
This is a custom engine, not WordPress templating. A name resolves to `tpl/<name>`, then `.html`, `.xml`, `.tpl`, and the result is cached per name. Syntax:
- `{var}` and dotted `{a.b.c}` (also matches keys that themselves contain dots, like `background.color`)
- `{TRUE var}…{/TRUE}` and `{FALSE var}…{/FALSE}` (the string `"false"` counts as false)
- `{IF a || !b ++ c}…{/IF}` (`++` means AND)
- `{@other/template}` to include another template

Values are inserted raw with no escaping, so callers must escape first.

### Data model
There are four tables, `{$wpdb->prefix}flgallery_{albums,galleries,images,settings}`. Their schemas live in `inc/db.*.php`: each file sets a `$query` string, which `getTableSchemas()` collects for `createTables()` (activation) and `upgradeTables()` to pass to `dbDelta`. To change a schema, edit the `db.*.php` file and add an upgrade step that calls `upgradeTables()`.
- `images` rows belong either to a media-library album (`album_id`) or to a gallery (`gallery_id`). Adding album pictures to a gallery creates copies. `path` is relative to `wp-content/flgallery/images/`, or starts with `/` (relative to the site root) for pictures imported from the WordPress Media Library.
- `settings` stores key/value rows per `(gallery_id, gallery_type)`, so switching a gallery's type keeps the settings of the other types. Values missing from the table fall back to the defaults in `settings/<Type>.xml`.
- Access control uses legacy numeric user levels, derived in `getUserInfo()` from the `level_N` capabilities: level ≥ 5 can edit any gallery, lower levels only galleries they authored (`flgalleryGallery::$auth`). Uninstall requires `delete_plugins` and a nonce.

### Files on disk
Runtime content lives in `wp-content/flgallery/{images,xml,uploads,tmp}`. `flgalleryImage::resized()` uses GD to create resized copies at `tmp/img-<name>.<W>x<H>.<ext>`. It skips resizing when less than ⅓ of `max_execution_time` remains (`flgalleryStats::deadline()`), and adds images that crash during processing to `tmp/imgBlacklist.txt`.

### Admin UI and adding pictures
There are three menu pages: `flgallery` (`flgalleryAdmin::manage`), `flgallery/media` (`flgalleryMedia::manage`) and `flgallery/about`. Requests are dispatched through `switch ($_REQUEST['action'])` blocks. AJAX goes through the single `wp_ajax_flgalleryAdmin` hook, which requires `edit_posts` and dispatches on the `ajax_action` parameter.

The admin CSS predates the modern WordPress admin, which restyles shared classes:
- `.button` gets theme-colored borders, focus rings and a 40px `min-height`.
- Links get a focus ring on `:focus`.

`css/admin.css` overrides these inside plugin panels. It removes rings only for `:focus:not(:focus-visible)`, so keyboard users still see focus. Collapsible panels (gallery cards, the Preview box) use WordPress's `.postbox-header` / `.handle-actions` / `button.handlediv` markup. The plugin's JS toggles the `closed` class itself, because WordPress's `postbox.js` isn't loaded on these pages.

Each way of adding pictures has a tab method in `media.class.php`, a `tpl/media/add-*.html` template and a `js/add-*.js` script. All of them end in `flgalleryMedia::addFiles()`, which accepts only real JPEG/PNG/GIF files (checked with `getimagesize`) and gives them random names:
- The multi-file uploader (`js/add-html5upload.js`) posts each file to `flgalleryUpload` (`inc/ajaxUpload.class.php`, nonce `flgallery-upload`) into `uploads/<upload_id>/`. The form submit then imports and deletes that folder.
- "Import from Folder" is limited to folders inside `wp-content`, excluding plugins, themes and the plugin's own `images`/`xml`/`tmp` (`resolveImportFolder()`), because it can delete the source files.
